## Current state (checked against the DMT_TCM_DEV class bodies on 2026-10-30)

Status: delivered, tested in DMTPRE2 (2026-10-16 and 2026-10-19). 4117 chose WHAT is watched: the renderers declare it, read through DMT_RendererFactory, and the triggers do the restart.

### The process in order
1. **Freeze, when a task closes.** DMT_ApprovalChangeStep_Handler.updateTaskWithStatus stores a snapshot for the APPROVER'S VIEW: only the components (DMT_Items__c) of that approver's view, into DMT_TaskStatusWhenCompleted__c (DMT_ViewFieldStatusAtClose__c, DMT_TrackedComponents__c). It is not every renderer and not every field. Sanction Lines have no view, so nothing is tracked.
2. **Gate, on update, in the trigger.** It runs only at the three checkpoints below. Any other transition or stage reopens nothing.
3. **Compare.** DMT_ApprovalChangeStep_Helper.restartStaleApprovalTasks -> getRestartableTasks -> isTaskStale (L550), then DMT_SnapshotChildComparator for child rows. No snapshot, or no section for the object: not stale.
4. **Restart.** dispatchRestarts (L615) runs inline when fewer than SYNC_RESTART_RECORD_LIMIT (2, L155) records are stale, otherwise one DMT_RestartApprovalTasksPayload per record. restartTasksForRecord (L78) cancels the stale tasks, creates ONE replacement per Case (Subject 'Task', Not Started, no snapshot) and sets the Case to Pending.
5. **HPG values.** Not stale on fields -> enqueueCalloutTrackableChecks (L373) -> chained DMT_CalloutTrackableCheckPayload, asynchronous, each hop in its own transaction. The trigger never makes the callout inline.

### The three checkpoints (Opportunity and Line are the same)
| # | Condition (from oldMap) | Cases checked: Case.DMT_Passport_Sanction__c |
|---|---|---|
| 1 | old Draft, new Proposal, old DMT_DateToProposal__c not null | passport |
| 2 | old Proposal, new Approval | approval |
| 3 | old Ready to close, new Ready to close | readytoclose |

- Opportunity: DMT_OpportunityTriggerHandler.restartApprovalTasksOnOpportunityResubmission (L551), record type DMT_Opportunity only, StageName.
- Line: DMT_Line_Helper.restartApprovalTasksOnLineResubmission (L1401), record types TreasurySettlement and OtherProducts only, never Sanction, Status__c.
- Checkpoint 3 is an edit WHILE in Ready to close, not entering it. It compares fields and does not trust DMT_Is_Change_in_Ready_to_close__c.

### Facts that are easy to get wrong
- 'Sanction' has two meanings: the value of Case.DMT_Passport_Sanction__c (passport / approval / readytoclose) and the Sanction Line record type, which never takes part. Do not use 'sanction' in new names for the checkpoint logic.
- Restartable task = Status != Cancelled AND DMT_Not_Restart__c = false AND DMT_ViewStatusAtClose__c != null. A replacement has no snapshot, so a second save does not reopen it. A new snapshot appears only when an approver closes the replacement.
- Tasks without a snapshot are never cancelled by a restart, so old replacements stay open forever and can look like duplicates.
- Approved (green, Finished/Yes) Cases DO reopen when a tracked field changes. Decided 2026-10-19; the old CIBGLOBALD-3233 green protection stays out.
- DMT_TrackedComponents__c scopes the comparison. Blank (legacy snapshot) = every tracked component.
- Restart failures are swallowed into DMT_LogExceptionPayload. If a test 'does nothing', check the exception log.
- Passport traffic light (dmt_passport_opportunity.getWorkflowColor): Pending or In Progress = yellow, Finished No = red, Finished Yes = green.
- Idempotent since CIBGLOBALD-4800: restartTasksForRecord re-reads FOR UPDATE and keeps only open tasks (L91); dispatchRestarts skips tasks already dispatched in the transaction (restartDispatchedTaskIds, L612). Keep both.
- Measured cost: one restarted record ~10-13 SOQL, 9 DML, ~0.6 s CPU. Opportunity checkpoint with no restart ~18 SOQL. Line trigger base ~29 SOQL. The org hits 'Too many SOQL queries: 101' often.
- DMT_ApprovalChangeStep_Handler.previewCompareTasksFromCase (L365) is a SEPARATE, older comparison. It looks at all Cases with no DMT_Passport_Sanction__c filter and can disagree with the gate. Missed in 4117.

## Framework map (verified by reading code 2026-10-13, DMT_TCM_DEV mirror in working tree)

### A. CLOSE - freeze the snapshot
Entry points that call `DMT_ApprovalChangeStep_Handler.updateTaskWithStatus(taskId, createPdf)`:
- OmniStudio IP ApprovalChangeStep -> `DMT_ApprovalChangeStep_Handler.call()` actions `saveValuesUpdate` (close, true) / `saveValuesInsert` (new task, false)
- DMT_ApprovalValidation_Service.updateApprovalStep (closes current task, creates next-approver task and freezes it too)
- DMT_ApprovalTemplate_Controller (2 spots), DMT_TaskApprovalFlowService (close = true, new task = false), DMT_TaskManager, DMT_Passport_Helper.createTask
- Bulk: DMT_Massive_Task_Closure_Service.confirmMassiveClosure (massive closure modal; same builder, bulk queries)

What updateTaskWithStatus does:
1. Loads Task + Case; line vs opp from `Case.DMT_LineOpportunity__c` ('L'/'O'); loads the record with DMT_View_Selector.getLineWithRelatedData / getOpportunityWithRelatedData.
2. Finds the approver view: task owner queue -> DMT_Approver__c by group DeveloperName -> `Approvers_View__c` (OtherProducts) / `Approvers_View_Treasury__c` (TreasurySettlement) / `Approvers_View_Opportunity__c` (DMT_Opportunity). Sanction = no view = not tracked.
3. Loads the view's DMT_Items__c; `resolveTrackedFieldsForItems` asks each component via DMT_RendererFactory.getTrackedFieldsByObject / getTrackedFields -> `Object.Field` map; also records which tracked components the view has.
4. `resolveChildSectionsForItems` + `queryDirectChildSections` -> child rows (ChildSection declared by MultiObject renderers, e.g. Custom_Association_Client__c for Client, Participants, Products).
5. `DMT_TaskSnapshotService.buildSnapshotJson` -> JSON with sections `line` or `opportunity`, `customAssociationClientList`, child sections keyed by snapshotSectionKey, and `calloutTrackedValues`.
6. Creates/updates `DMT_TaskStatusWhenCompleted__c`: `DMT_ViewFieldStatusAtClose__c` (JSON), `DMT_AllFieldsInStatus__c` ('Obj.Field;Obj.Field'), `DMT_TrackedComponents__c` (new, 4117; semicolon list), `Case__c`; links `Task.DMT_ViewStatusAtClose__c`.
7. HPG callout-tracked components (DMT_CalloutTrackableRenderer: DMT_Default/Other/OpportunityClientRenderer, ClientNBC): never fetched inline (uncommitted-work error). A `DMT_CalloutTrackableFreezePayload` is enqueued; `DMT_ApprovalChangeStep_Helper.freezeCalloutTrackableBaseline` later merges live values into the snapshot JSON under `calloutTrackedValues`.

### B. WATCH / REOPEN - on stage change
Triggers (AFTER UPDATE):
- [SUPERSEDED 2026-10-19: Lines now have the same 3 checkpoints as the Opportunity] Line: DMT_Line_TriggerHandler.afterUpdate -> `DMT_Line_Helper.restartApprovalTasksOnLineResubmission`. Qualifies: RT TreasurySettlement/OtherProducts (Sanction excluded), oldLine.Status__c = Draft AND new <> Draft AND oldLine.DMT_DateToProposal__c != null (genuine resubmission). Cases = ALL Cases of the Line. Section key 'line'.
- Opportunity: Opportunity.trigger -> `DMT_OpportunityTriggerHandler.restartApprovalTasksOnOpportunityResubmission`, RT DMT_Opportunity only, 3 checkpoints each filtered by `Case.DMT_Passport_Sanction__c`:
  1. Draft -> Proposal with old DMT_DateToProposal__c != null -> 'passport'
  2. Proposal -> Approval -> 'approval'
  3. Ready to close -> Ready to close (edit while parked) -> 'readytoclose' (compares watched fields; does NOT trust DMT_Is_Change_in_Ready_to_close__c)
  Before-update `stampDateToProposal` sets DMT_DateToProposal__c on Draft -> Proposal (replaced the AfterCreateOpportunity flow part; the flow's compare/restart branches were removed, description cites 4117).
Both call `DMT_ApprovalChangeStep_Helper.restartStaleApprovalTasks(caseIdToRecordId, records, 'line'|'opportunity', DMT_SnapshotChildComparator.forRecords(...), originClass)`:
1. `getRestartableTasks`: Tasks on those Cases with Status != Cancelled AND DMT_Not_Restart__c = false AND DMT_ViewStatusAtClose__c != null.
2. `getSnapshots` of those tasks; clone Trigger.new records; `mergeRelationshipFields` adds 'Client__r.Name' style fields via one SOQL.
3. `isTaskStale` per task: snapshot blank / no section for the object -> false (never restart on old/missing data). Compares live record (JSON round-trip) vs frozen for `DMT_RendererFactory.getTrackedFields(trackedComponentsForSnapshot(snapshot), record)`, blank normalized to null. Scoped by `DMT_TrackedComponents__c` (blank = all tracked components). Then child rows via `DMT_SnapshotChildComparator.hasChanges` -> `rowsDiffer` (row count / Id set / tracked fields).
4. Stale -> grouped per record -> `dispatchRestarts`: < SYNC_RESTART_RECORD_LIMIT records sync (10 at the time, 2 since 2026-10-19) `restartTasksForRecord`, otherwise `DMT_RestartApprovalTasksPayload` via DMT_AsyncOrchestrator (-> DMT_AsyncDispatcher -> restartTasksForRecord).
5. Not stale -> `enqueueCalloutTrackableChecks`: chain of `DMT_CalloutTrackableCheckPayload` (one per component, each hop own transaction) -> `checkCalloutTrackableComponent` compares frozen vs live HPG values; mismatch -> restartTasksForRecord for that task and abort chain.
`restartTasksForRecord` (savepoint per record): all stale tasks -> Cancelled; ONE new Task per Case cloned from its oldest stale task (Not Started, Subject 'Task', DMT_ViewStatusAtClose__c null); Case reset: Status Pending, DMT_IsInRevision__c false, OwnerId = task owner. Exceptions are swallowed into DMT_LogExceptionPayload (silent failure - check the exception log object when a test "does nothing").
The new Task then goes through Task.trigger -> DTM_Task_Helper (DMT_Task__e for Passport refresh, 4617).

## BUG FOUND + FIX (2026-10-13) - Opp 'Approval Process Data' false restart
- Symptom (DMTPRE2): resubmitting an Opportunity with NO change cancelled+recreated the task every time.
- Cause: `DMT_ApprovalChangeStep_Handler.resolveTrackedFieldsForItems` used `if (byObject non-empty) {...} else {getTrackedFields}`. DMT_OppApprovalProcessDataRenderer returns BOTH: parent fields (DMT_SPPI_Status__c, DMT_SPPI_User__c, DMT_SPPI_File_Uploaded__c, DMT_Financial_Sponsors__c) in getTrackedFields and only child objects in getTrackedFieldsByObject. So the 4 parent fields were never frozen, while the gate (isTaskStale) compares getTrackedFields of every component -> live false/'Passed' vs frozen absent = changed. Checkboxes are never null, so it triggers even on untouched records.
- Why it was not seen in DMT_TCM_DEV: code is identical there; TCM approver views are NBC-style (no 'Approval Process Data' item; only 3 of 14 opp approvers have it), PRE2 has it in 11 of 24. Read-only Apex scan of all tracked components in PRE2: this is the only component with the gap.
- Fix (one file): DMT_ApprovalChangeStep_Handler.resolveTrackedFieldsForItems now ALWAYS adds getTrackedFields() (prefixed with sObjectApiName) in addition to the byObject map (dedupe already exists). Applied locally on a fresh TCM retrieve, deployed to DMT_TCM_DEV (class only, DMT_ApprovalChangeStep_test 13/13 pass). NOT deployed to DMTPRE2.
- Side effect to remember: snapshots frozen BEFORE the fix for Opp views with Approval Process Data still lack those 4 fields -> one false restart on next resubmission for tasks already open.
